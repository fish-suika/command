## 1. ゲーム概要

制限時間内に、画面に出る矢印コマンドを速く正確に入力し続けるスコアアタック。
1プレイは短く、ミスしても続けられ、終わったらすぐ再挑戦できる。「あと1回だけ」と思わせることがゴール。

優先順位は **入力の気持ちよさ ＞ テンポ ＞ 分かりやすさ ＞ リトライの速さ ＞ 機能の数**。

## 2. 技術方針

- 素の JavaScript ＋ HTML/CSS。フレームワーク・three.js は使わない
- 矢印は DOM の文字として表示する。演出は CSS アニメーション
- 画像・音声ファイルはゼロ（音は Web Audio の波形合成）
- 前2作と同じく `src/` の分割ソースを `build.sh` で1枚の HTML に結合する
  - 出力: `command.html` と `index.html`（GitHub Pages 用のコピー）
  - 検証ページ: `verify.html`（ロジックのみを結合）
- 対応端末: **PC（キーボード）＋スマホ（タッチ）**。縦持ち・横持ちどちらでも遊べる

## 4. 状態

```
state = {
  phase: 'ready' | 'playing' | 'result',
  timeLeft,        // ミリ秒
  score,
  combo,           // Phase 1 は数えて表示するだけ
  maxCombo,
  cleared,         // クリアしたコマンド数
  inputs,          // 正しく押したキーの総数
  misses,
  command,         // 例: ['U','R','D']
  pos,             // 次に押す位置
  gauge,           // 連続クリア数（0〜GAUGE_MAX-1。ミスで0）
  boosts           // 時間が増えた回数
}
```

## 5. ゲームの流れ

1. **ready**: 中央に「矢印キー／ボタンでスタート」。最初の方向入力（どの方向でも）でスタートする。その入力はコマンドの1文字目としては扱わない
2. **playing**: 30秒間（2026-10-02 に60秒から短縮）。コマンドを順に入力する
3. **result**: 時間切れになったら結果を表示（スコア・入力数・ミス・最大コンボ・正確さ）と大きな `もう一度`
   - もう一度 は Enter／Space／タップで押せる。押したら ready を挟まず **即 playing** で始まる
   - 時間切れ直後の連打で誤って もう一度 しないよう、結果表示から **0.6秒** は入力を受け付けない

## 6. ルール（Phase 1 の初期値。遊んでから調整する）

すべて `10-logic.js` の先頭に定数としてまとめる。

| 定数 | 初期値 | 意味 |
|---|---|---|
| `TIME_LIMIT` | 30000 ms | 制限時間 |
| `LEN_START` | 2 | 最初のコマンドの長さ |
| `LEN_STEP` | 3 | 何コマンドクリアごとに1個長くなるか |
| `LEN_MAX` | 20 | 長さの上限（2026-10-02 に 9 から変更。11個以上は1段10個の2段表示） |
| `PTS_PER_KEY` | 100 | 矢印1個あたりの基本点 |
| `GAUGE_MAX` | 10 | 何コマンド連続クリアで満タンか |
| `GAUGE_BONUS` | 3000 ms | 満タンで増える時間 |
| `MISS_PENALTY` | 50 | ミス1回の減点 |

- **長さ** = `min(LEN_START + floor(cleared / LEN_STEP), LEN_MAX)`
- **コマンド生成**: 各文字を4方向から一様ランダムに選ぶ。同じ方向の連続も許す。乱数関数は引数で差し替えられるようにする（検証用）
- **正解キー**: `pos` を進め、`inputs` を+1。最後まで入力したらクリア
- **クリア時**: 
  - 得点 = `PTS_PER_KEY × 長さ`（速さによる加点はない）
  - `score += 得点`、`cleared += 1`、`combo += 1`、`maxCombo` を更新
  - **ゲージ**: `gauge += 1`。`GAUGE_MAX` に達したら `gauge = 0`、終了時刻を `GAUGE_BONUS` ぶん延ばし（残り時間 +3秒）、`boosts += 1`
  - **同じ処理の中で** 次のコマンドを生成して表示する（待ち時間ゼロ）
- **ミスキー**: `misses += 1`、`combo = 0`、`gauge = 0`、`score = max(0, score − MISS_PENALTY)`。**`pos` はそのまま**で続行
- **ACCURACY** = `inputs / (inputs + misses)`（両方0なら 100%）。小数点以下切り捨ての%表示
- 制限時間が0になった瞬間に入力中のコマンドは破棄し、result へ移る

## 7. 画面

- 上部 HUD: `スコア` / `タイム`（小数1桁、残り10秒で色を変える）/ `コンボ`
- HUD の下に細い**時間ゲージ**（高さ6px）。連続クリア数に応じて伸び、満タンで空に戻る。満タン時は タイム の数字が緑に光って拡大し、横に `+3秒` が浮かんで消える（中央のコマンドには重ならない位置）
- 結果画面に `時間ボーナス`（延びた合計秒数、例 `+6秒`）を `最大コンボ` の下に表示する
- 中央: コマンドを大きく表示する。入力済みは薄く、**次に押す1個を強調**する。9個でもスマホの縦画面で1行に収まる大きさに自動で縮める
- 正解・ミスの最低限のフィードバック: 正解した矢印が一瞬光る／ミスで次の矢印が赤く揺れる（0.15秒程度。次のコマンドを隠さない）
- 下部（タッチ端末のみ表示）: ↑↓←→ の十字ボタン
  - `pointerdown` で反応（`click` の遅延を避ける）
  - `touch-action: manipulation` などでダブルタップ拡大・スクロールを止める
  - タッチ端末の判定は `matchMedia('(pointer: coarse)')`
- キーボード: 矢印キーと WASD（W=↑ A=← S=↓ D=→）の両方で入力できる。矢印キーでページがスクロールしないよう `preventDefault`。押しっぱなしのキーリピートは無視する（`e.repeat`）

## 8. 音（Phase 1 は最小限）

- 正解キー: 短い「ピッ」
- コマンドクリア: 少し高い音
- ゲージ満タン（時間延長）: 上昇する2音のチャイム
- ミス: 低い音
- 終了: 短い結果音

## 12. Phase 2（気持ちよさ）

Phase 1 を遊んだうえで、コンボ倍率・演出・音を加えた。実装計画は `docs/superpowers/plans/2026-10-02-phase2-feel.md`。

### 本人が決めたこと（2026-10-02）

- コンボは **段階的な倍率**。ミスで ×1 に戻る
- 難易度は **長さだけ**（WASD 出題・1コマンドごとの制限時間は入れない）

### 絶対に守ること

演出で次のコマンドを隠さない・見づらくしない。リトライまでの時間を延ばさない（結果のカウントアップは 0.5秒で、RESULT_LOCK 0.6秒の内に終わる）。

### 倍率

| 定数 | 値 | 意味 |
|---|---|---|
| `COMBO_STEP` | 10 | 何コンボごとに倍率が上がるか |
| `COMBO_RATE` | 0.5 | 1段あたり上がる倍率 |
| `COMBO_MULT_MAX` | 3 | 倍率の上限 |

- 倍率 = `min(1 + COMBO_RATE × floor(combo / COMBO_STEP), COMBO_MULT_MAX)`（×1 → ×1.5 → ×2 → ×2.5 → ×3）
- 段（tier）= 0〜4（×1 が 0、×3 が 4）。色・音の切り替えに使う
- クリア時は **先に** `combo` を増やし、得点 = `round(PTS_PER_KEY × 長さ × クリア後のコンボの倍率)`
- ミスで `combo = 0`（倍率 ×1）。減点 `MISS_PENALTY` は倍率の影響を受けない
- 状態に `maxMult`（到達した最大倍率）を追加。ミスで戻らない
- **節目**: `combo` が 5、または `COMBO_STEP` の倍数のとき

### 演出

| 演出 | 内容 |
|---|---|
| 倍率バッジ | COMBO の数字の横に `×1.5` など。×1 では非表示。段が上がると弾む（scale 1.6→1、0.25秒） |
| 段の色 | `#app` の `--tier-color`（×1.5 水色 / ×2 緑 / ×2.5 黄 / ×3 ピンク）。他の演出も共通で使う |
| 節目表示 | コマンドの上の固定高さの欄に `10コンボ！`。0.6秒で上へ浮いて消える。30コンボ以上は大きく光彩付き |
| クリアの輪 | コマンドの後ろで広がって消える輪（0.3秒、`--tier-color`） |
| スコアの弾み | クリアでスコアの数字が弾む（scale 1.15→1、0.12秒） |
| 背景 | 倍率 ×2 以上で `--tier-color` の薄い放射グラデーション（不透明度 0.06〜0.1）。ミスで消える |
| ミス | 既存の赤い揺れに加え、コンボ2以上が途切れたときだけ コンボ の数字が赤く光る |
| リザルト | スコアを 0 から 0.5秒でカウントアップ。最大コンボに到達倍率を添える（例 `42（×3）`） |

演出はコマンド（`#cmd`）の位置・大きさを変えない。節目表示の欄は高さ固定、輪は別要素で `#cmd` の幅の計測に影響しない。

### 音

| 音 | 内容 |
|---|---|
| `hit(i)` | 三角波・0.08秒。コマンド内の i 番目（0始まり）ほど高い。ハ長調の音階 ド(262Hz)→レ→ミ…、20個目はラ(1760Hz)（最大20個なので低いドから始める。半音階は不安な響きになるので使わない） |
| `clear(i)` | 最後の1打。`hit(i)` とまったく同じ（音階の次の音・同じ音色と長さ）。最後だけ違う音にすると浮いて聞こえる |
| `milestone(i)` | 節目の3音。最後の1打が鳴り終わってから、その上の「ド・ミ・ソ」を3つ続ける。**boost と同時のときは鳴らさない** |
| `tick()` | 残り5〜1秒の各秒の切り替わりで短いクリック音。時間延長で秒数が増えたときは鳴らさない |
| `boost()` | ソ→ド。`end()` はド→ミ→ソ→ド。`miss()` は Phase 1 のまま |
| `end()` | 結果発表らしく4音に延長 |

## 13. Phase 3（ハイスコア保存）

本人の選択により、Phase 3 は **自己ベストの保存と表示だけ**。ランク・特殊コマンドなどは行わない。

### ロジック（`10-logic.js`、DOM・保存に触れない）

`judgeBest(score, best)` → `{ isNew, best, diff }`。`isNew = score > best`（同点は更新ではない）。更新なら `best = score, diff = 0`、そうでなければ `best` は据え置きで `diff = best - score`。score 0 かつ best 0 は更新ではない。

### 保存（`50-store.js`）

`Store.loadBest()`（0以上の整数。無い・壊れている・読めないときは 0）と `Store.saveBest(n)`。localStorage のキーは `command.best`。すべての localStorage アクセスを try/catch で囲み、private モードや `file://` で例外が出ても保存なしでそのまま遊べる。`verify.html` には含めない。

### 終了処理（`95-boot.js`）

`tick()` が true を返したとき・`press()` が `'end'` を返したときの両方から、共通の `onEnd()` を呼ぶ（1ゲーム1回）。`judgeBest(S.score, best)` を計算し、更新なら `best` を更新して保存し `Snd.record()`、更新でなければ `Snd.end()`（両者は重ならない）。結果は view へ渡す。

### 表示

| 画面 | 内容 |
|---|---|
| 結果（更新） | スコアの下に `自己ベスト更新！`（アクセント色・光彩、0.5秒の弾むアニメーション） |
| 結果（非更新） | `ベスト 12,345`。best > 0 かつ diff > 0 のとき、その下に `ベストまで あと 1,230` |
| ready | best > 0 のとき、開始メッセージの下に小さく `ベスト 12,345` |

結果画面は行間を詰め、375x812 でも もう一度 が見える。カウントアップは従来どおり 0.5秒（`RESULT_LOCK` 内）。

### 音

`record()`: ド ミ ソ ド↑ ミ↑ ソ↑ とつなぎ、最後に ド↑↑ を長く伸ばす。ハ長調のみ（`note(d)`）。既存の音は変更しない。

### 検証

`verify.html` に `judgeBest` の5件（初プレイ・更新・同点・下回る・0/0）を追加（計27件）。

## 15. 制限時間モード（30秒・60秒・90秒）

### ロジック（`10-logic.js`）

- `CFG.MODES = [30000, 60000, 90000]`。`CFG.TIME_LIMIT`（30000）は既定のモード
- 状態に `timeLimit` を追加。`createState(limit)` は省略時 `CFG.TIME_LIMIT`、`timeLeft` は `limit` で始まる
- `startGame` は現在の `s.timeLimit` を保ったまま作り直し、`endAt = now + timeLimit`。このためリトライは同じモードで始まる
- `setMode(s, limit)`: `phase` が `ready` / `result` で、かつ `limit` が `CFG.MODES` にあるときだけ `timeLimit` を変えて `true`。`ready` では `timeLeft` も更新（HUD に出る）。`result` では表示中の結果（スコア等）に触れず、次のリトライで遊ぶ時間だけが変わる。それ以外は `false`

### 保存（`50-store.js`）

自己ベストはモードごと。キーは `command.best.<秒>`（例 `command.best.30`）。`loadBest(limit)` / `saveBest(limit, n)`。**移行**: `command.best.30` が無く旧 `command.best` があれば、それを30秒モードのベストとして使う（旧版は30秒で記録していた）。localStorage アクセスはすべて try/catch。

### 起動（`95-boot.js`）

`best` は選択中モードのベスト。モード変更のたびに Store から読み直す。ゲーム終了時の `judgeBest` と保存は、いま遊んだモードに対して行う。

### UI

- `30秒` `60秒` `90秒` の3ボタン（選択中はアクセント色）。ready（開始メッセージの下・ベスト行の上）と結果（もう一度 の上）に出し、プレイ中は隠す
- 操作: タップ（`pointerdown`、方向入力・リトライとは別扱い）、または Digit1〜3 / Numpad1〜3（ready・result のときだけ）。ready では タイム とベスト行がすぐ変わる。結果では選択だけが変わり、結果表示はそのまま。もう一度 のラベルが `もう一度（60秒）` のように選択中のモードを示す。`RESULT_LOCK` は開始にだけ効き、モード選択には効かない
- ready に `1・2・3 キーでも切替` を小さく表示
- 375x812 でも結果画面（モード選択・もう一度 を含む）がスクロールなしで収まる

### 検証

`verify.html` に6件追加（計33件）: 既定モード・ready での切替と endAt・playing 中は不可・不正値・リトライでモード維持・result での切替が結果を変えず次のリトライだけ変えること。
